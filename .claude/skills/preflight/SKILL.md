# preflight

Run the same gates as `.github/workflows/ci.yml` locally. The Makefile targets
are authoritative — `make <target>` runs the exact CI-equivalent command.

## Default: fast gates (detection + adapters)

These are the invariants most easily broken by edits and cheapest to run. Start
here unless the user asks for the full suite:

```bash
make validate
```

That runs (from the Makefile):
- `python3 detection_scanner/scripts/validate.py --quiet`  — corpus validity (0 fail)
- `python3 detection_scanner/scripts/export_artifacts.py` + `git diff --exit-code
  detection_scanner/exports/`  — export determinism (regenerated bytes must match)
- `scripts/check-adapter-sources.sh`  — tier-2 adapter source preflight

**If the export-determinism step fails**, exports are stale: `export_artifacts.py`
already regenerated them, so stage `detection_scanner/exports/` alongside the
content change and re-run. This is the single most common CI surprise.

## Full suite (mirrors all 5 CI jobs)

Only when the change touches backend/agent/ui code, or the user asks for
everything. These build Docker / run npm and are slow:

```bash
make ci          # test (backend+agent+ui) + validate (detection+adapters)
```
Or run individual code gates:
- `make test-backend`  — pytest inside the prod image (CI `backend`)
- `make test-agent`    — `go build/vet/test -race` (CI `agent`)
- `make test-ui`       — `npm ci && vite build && vitest` (CI `ui`)

`make test-backend` and `make ci` build the Docker image and need Docker running.

## How to run it

1. Pick the scope from what changed (`git diff --name-only`): content-only →
   `make validate`; code touched → the relevant `make test-*` or `make ci`.
2. Run it, capture output. Report the verdict per gate — which passed, which
   failed, and the exact failing command/output. Do not claim green unless every
   gate you ran exited 0.
3. On the export-determinism failure specifically, apply the stage-and-rerun fix
   above rather than reporting it as an opaque failure.
4. Offer to commit at sensible boundaries (named-file `git add`, no `-A`); do not
   open a PR unless asked.
