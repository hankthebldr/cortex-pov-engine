# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

CortexSim — an enterprise detection simulation engine for Palo Alto Networks Domain Consultants. It generates controlled, high-fidelity signals into customer Cortex environments (XSIAM/XDR) to validate detection logic across the full `detection_type` vocabulary — **`BIOC | XQL | Analytics | Correlation | IOC | ABIOC | Prevention`** — plus the XDM modeling-rule normalization substrate (`detections.modeling_rules[]`) and stitching/grouping. Think "MITRE Caldera's opinionated nephew" — not a red team C2, but a detection quality assurance engine.

**The Cortex connection is OPT-IN and READ-ONLY** *(the Phase 1 "no connection" rule is superseded; corrected 2026-08-06 — the old wording said alert read-back was "parked", which contradicted the Measurement-loop section below)*. SimCore's job is still to generate signal INTO the environment via agent-based execution, and it **never writes** to Cortex — `CORTEXSIM_XSIAM_ALLOW_WRITE` and `CORTEXSIM_XSIAM_ALLOW_DESTRUCTIVE` stay default-off. When a credential is configured it **does** read out, on three opt-in paths: tenant health/metrics (`/healthcheck`, XQL over `metrics_*`, `core/integrations/xsiam/`); **alert read-back** for auto-validating seeded results into evidence-backed MTTD (`core/connectors/`, the measurement loop below); and **Tier-2 verification** XQL. Nothing is polled without a flag. **`POST /api/connectors/{kind}/preflight`** answers "is my connection working?" *before* the POV instead of mid-run — staged (config → dns_tls → auth → scope → datasets → clock → response_layer), every stage reported even when an earlier one degraded, and every response carries `queries_issued` so a preflight run against an injected transport cannot be quoted as tenant proof.

> ***tenant-verified is 0.*** No run and no assertion in this repo has ever been executed against a live Cortex tenant. Every green in the test suite, the console and this file comes from an injected transport. **Authored is not proven** — do not report the two as one number. The console's Launch gate states this verbatim and is the right model to copy. Executing on an endpoint is a different claim from detection against a tenant: one green CI run on a hosted Windows runner and one Linux lab run (`pov-target-01`, 2026-11-10, no credential on that SimCore) prove that steps ran, never that Cortex saw them.

## Branching & Contribution Model

**Read `CONTRIBUTING.md` before opening a PR.** Summary of the rules that bind
your behaviour in this repo:

```
  feature/*  fix/*  docs/*  chore/*   ->  dev  ->  main
             QA Gate A  ^                  QA Gate B  ^
```

- **Never commit or push directly to `main`.** `main` is what a DC deploys into a
  customer lab; it only ever advances by a merge from `dev` (or an expedited
  `hotfix/*` PR, which must then be merged back down into `dev` in the same pass).
- **Cut every topic branch from `dev`**, named `<type>/<area>-<slug>` where type is
  `feature|fix|docs|chore|hotfix` and area is one of `api agent ui scenarios ttp
  adapters shelf infra docker ci docs deps`. One branch, one task — if describing
  it needs the word "and", it is two branches.
- **Rebase topic branches onto `dev`; merge `dev` into `main`.** Never rebase `dev`
  or `main`.
- **Commit aggressively at sensible boundaries, staging by name.** `git add <path>`
  only — never `git add -A`, `git add .`, or `git commit -a`. A release-prep pass
  is 6-8 commits, not one and not forty.
- **Do not open PRs unless asked.** Commits land on the topic branch; `gh pr create`
  waits for an explicit "open a PR" / "ship it".
- **Force-push, `reset --hard`, and deleting anything that still holds unmerged or
  uncommitted work require confirmation.** Merged branches and their worktrees are
  deleted once nothing on them can be lost (`CONTRIBUTING.md` § *Cleaning up*).

### The two gates, in one line each

- **Gate A (`feature/*` -> `dev`)** — all 8 ubuntu CI jobs green (the 9th, `windows`, runs but is not yet required: it has run green three times, most recently run 43037077022 at `e434efa` with all nine jobs green, and making it required is decision DOCS-12, Henry's), plus the author's own
  evidence in the PR body: what was observably wrong, how the fix was verified,
  and **proof the new guard fails without the fix**. A test never observed failing
  is an assumption with good syntax.
- **Gate B (`dev` -> `main`)** — releasable-into-a-customer-lab: image *parity*
  (the built image ships what the tree has, not merely compiles), counted ground
  truth regenerated into README/CLAUDE.md, CHANGELOG updated, and every public
  claim in the README actually backed.

### Gate A5 — the honesty checks that no CI job can express

These are the ones that matter most here, because the failure mode is not a red
build but a **false claim about a customer's security coverage**:

- **Authored is not proven.** `tenant-verified` is 0 and stays 0 until a run
  executes against a live Cortex tenant. Never report the two as one number.
- **A zero is degraded, not ok.** "None shipped" and "none authored" must never
  render as the same response.
- **Tolerance hides bugs.** An unrecognized shape must raise, not read as empty —
  the tolerant fix keeps the bug and greens the test.
- **No write path to Cortex.** `CORTEXSIM_XSIAM_ALLOW_WRITE` /
  `CORTEXSIM_XSIAM_ALLOW_DESTRUCTIVE` stay default-off.

> **Squash-merge trap.** A squash-merged PR leaves your local branch showing
> "unmerged" commits whose content is already on the target. Judge by content, not
> commit count: `git diff <target>..<branch> --diff-filter=A --name-only`, then
> check whether those files exist on the target. Commit counts lie; blobs do not.

## Build & Run Commands

### Quick start (local dev)
```bash
cp .env.example .env        # set CORTEXSIM_SECRET etc.
./scripts/dev-up.sh         # one-shot: builds the image + brings up SimCore via docker compose
```
`scripts/dev-up.sh` is the canonical easy-deploy entry point (`[--dev] [--apply]`; an
unknown argument exits 2). `.env.example` documents all 36 `Settings` fields (counted
2026-11-11 on the beta-readiness merge with dev; `tests/test_env_example_coverage.py` fails on a field it lacks), including
the master-key guard the compose stack enforces. **Under docker compose the container
never reads `.env`:** `docker-compose.yml` passes only `CORTEXSIM_ENV`, `_SECRET`,
`_BIND`, `_ALLOWED_HOSTS`, `_CORS_ORIGINS` and `_TRUSTED_PROXIES` (`_PORT` and `_VERSION`
shape the port mapping and the image tag). Every other setting keeps its default in a
compose deployment until the compose file names it; the template marks the split.
Re-running `dev-up.sh` over an existing `.env` that has no `CORTEXSIM_ALLOWED_HOSTS`
warns, starts compose with this host's short and fully qualified names **for that
bring-up only**, and leaves `.env` untouched. `scripts/dev-up.sh --apply` writes the
line and keeps the previous file under `.env-backups/<UTC>/.env`. A plain
`docker compose up` afterwards drops an unpersisted value. A CNAME, `/etc/hosts` alias
or Tailscale name still has to be added by hand.


### Go Beacon Agent
```bash
cd agent && go build -o ../bin/cortexsim-agent .
./bin/cortexsim-agent --server http://localhost:8888 --id my-jumpbox --interval 10

make agent-dist   # cross-compile {linux,darwin}x{amd64,arm64} + windows/amd64 -> agent-dist/ + SHA256SUMS
```
Go module: `github.com/hankthebldr/cortexsim/agent` — Go 1.21+, stdlib only (no external deps).
The module path is an **internal import path only** — nothing resolves it over the network.

**SimCore serves the beacon.** `scripts/build-agent-dist.sh` (via `make agent-dist`)
and the `agent-builder` stage in `core/Dockerfile` cross-compile the matrix with
`CGO_ENABLED=0 -trimpath -ldflags="-s -w"` (~5 MB each) into `agent-dist/`, which
`GET /api/agents/binary` hands to the target. `docker build` / `make build` bakes
the matrix into the image (compose does not shadow `/app/agent-dist`); a **host-run
dev SimCore needs `make agent-dist` once** or `/api/agents/binary` returns an
actionable 404. `agent-dist/` is a build artifact — do not commit it.
**The matrix is five targets, Windows included** — `linux/{amd64,arm64}`,
`darwin/{amd64,arm64}`, `windows/amd64` (`.exe`). `agent/executor` stopped being
POSIX-only when the build-tag split landed (`platform_unix.go` / `platform_windows.go`),
and both producers now emit the `.exe`, so `GET /api/agents/binary?os=windows` serves
a real `PE32+` and `?os=windows` returns a PowerShell installer with no preflight
refusal. See the Windows-execution bullet below for what one green run on a hosted
`windows-2022` runner proved and what it did not.
`scripts/build-agent-dist.sh` builds into a staging directory inside `OUT_DIR` and only
then moves each binary in, removes binaries for targets no longer built, and moves
`SHA256SUMS` last, so a failed build leaves the old shelf whole. A relative `OUT_DIR` is
anchored to the caller's cwd. `-buildvcs=false` is deliberately **not** set:
`release.yml` reads `vcs.revision` back from the released beacons. So host-built and
image-built bytes differ for the same commit, and the script header says so.

### Rust Submodule Tools (signalbench, ackbarx, xdrtop)
```bash
make rust-dist            # static-musl linux/amd64 binaries -> rust-dist/ (needs docker, not rustup)
cd sources/<tool> && cargo build --release   # host build; needs a Rust toolchain + crates.io
```
`make rust-dist` (and the `rust-builder` stage in `core/Dockerfile`, which bakes the
same three binaries to `/app/rust-dist/` in the image) exists because
`cargo build --release` on a customer jumpbox needs rustup **and** crates.io egress —
the exact default-deny problem the beacon matrix solves for the Go side. `rust-dist/`
is a build artifact — do not commit it. **Caveat: the bytes are baked but not yet
servable** — there is no `/api/tools/binary/{tool}` route, so today the only way off
the image is `docker cp`. Getting a Rust tool onto a jumpbox is NOT yet a one-liner
the way the beacon is. `signalbench`'s plain `cargo build --release` also fails
(rc=101): `src/techniques/software.rs` does `include_bytes!("../../embedded_binaries/
pacemaker_helper")` and that file must be produced by building `helpers/pacemaker`
first — `make rust-dist` does both phases.

## Architecture

**Three-tier system:**

1. **SimCore** (`core/`) — FastAPI orchestrator, port 8888. Loads scenarios from YAML, manages tool lifecycle, dispatches tasks to agents or generates push bundles.
2. **cortexsim-agent** (`agent/`) — Go pull-model beacon. Polls SimCore for tasks, executes via identity harness, streams output back.
3. **React UI** (`ui/`) — SPA served by SimCore's static file mount at `/`. A rail of three journeys — Onboard & connect · Compose & simulate · Run & observe — plus Reference (design v26; see Cortex Branding and `docs/design/DESIGN-SYNC.md`).

**Execution modes:**
- **Pull** — agent polls SimCore, receives task, executes with identity harness, reports back
- **Push** — SimCore generates a self-contained bash bundle, a PowerShell (`.ps1`, Windows PowerShell 5.1 floor) bundle or K8s YAML; DC downloads and executes offline

**Execution lifecycle (pull mode is end-to-end working).** Launch → orchestrator seeds Results + enqueues a step task → the Go beacon polls `/api/agents/{id}/tasks`, iterates `steps[]` resolving identity agent-side, and POSTs per-step `/output` → `/complete`. Operators can **abort** a live run (`POST /api/runs/{id}/abort` → `aborted` state; the agent polls `GET /api/runs/{id}/control` every 2s and kills the in-flight process group). Live progress streams over **SSE** (`GET /api/runs/{id}/events` scoped + `GET /api/events` global). Agent liveness is **online/stale/offline**, derived from `last_seen` age with a background heartbeat sweep that emits `agent.status` SSE frames. The task queue is now **durable** (GAP-API-005 closed): it is a write-through cache over the `queued_tasks` DB table and is rehydrated on startup (`orchestrator.rehydrate()`), so a SimCore restart restores undelivered tasks and fails any orphaned `running` run whose task was lost. Push-mode runs reach a terminal `staged` state on bundle generation. Full surface: `docs/reference/api-and-agent-surface.md`.

**Run integrity (2026-11-10).** Several gates keep a run that never executed from becoming evidence:
- **A refused launch writes nothing; its dry run predicts it (2026-11-13).** Every refusal `POST /api/runs` can return is decided in `Orchestrator._evaluate_launch` before the Run row exists, so a refused launch leaves no Run, Result, task or event. `POST /api/runs/preflight` runs the same checks to the end and returns `{launchable, would_refuse_with, refusals[], checks[], warnings[]}`; `tests/api/test_runs_launch_preflight.py` holds the two to the same code and status for every refusal. Spec: `docs/superpowers/specs/2026-11-13-launch-gate-one-model-design.md` (slice 1).
- **Never executed is never matched (OPS-01).** A run lost on restart (`TASK_LOST_ON_RESTART`) has its Results stamped `not_executed`, as do rows refused after seeding by builds before 2026-11-13 (`LAUNCH_REFUSED`). The same holds for a run still queued, or aborted before delivery. `reconcile_candidates()` drops a pull run's beacon-step rows when no beacon ever collected its task (`delivered_at` NULL). The match is never made.
- **Abandoned runs are reaped (OPS-03).** A delivered run is reaped as `BEACON ABANDONED TASK` only when all four hold: its launch target is alive; its control channel has been silent for `CORTEXSIM_BEACON_LOST_AFTER_SECONDS`; no task for it is still queued; and every endpoint in its routing ledger has polled `/tasks` since it could have collected its task. A fan-out is never reaped while a second endpoint is queued, busy or staging. The marker says the `/complete` never arrived and lists possible causes; it does not guess one.
- **A late `/complete` is refused.** On a terminal run it is `409 RUN_ALREADY_TERMINAL`. The beacon retries `/complete`, and a 200 would read as accepted. One exception keeps host evidence (RG-RUNS-01): on an **aborted, delivered pull run** the `steps[]` are still upserted into `step_outcomes` and projected onto Results (`not_run` → `not_reached` / `not_executed`, which `apply_verdicts` never credits). The reply is still 409, with `detail.host_evidence_recorded`; status, output and verdict are untouched. A beacon that is gone, or predates `steps[]`, never sends that `/complete`, so those rows stay unjudged.
- **Retries count once.** The beacon now sends `task_id` and `agent_id` on `/complete`; SimCore records each in `run_task_completions` (`task:<id>`, else `agent:<id>`), and a repeat answers `200 {duplicate: true}` and changes nothing. A body with neither field is counted per POST, as before. Every non-streaming `/output` frame carries `frame_id` (`<task_id>:<n>`); `run_output_frames` stores a retried frame once (`duplicate: true`). Live streaming chunks carry none. Every frame now ends with a newline, so each `=== STEP` header starts a line; before, 4 of 5 frames were glued to the previous `--- exit_code=… ---` (seen on `pov-target-01` and on a dev SimCore at cc26ddf).
- **Refused or orphaned delivery is not evidence.** A task refused at the artifact-staging gate (`AGENT_CANNOT_STAGE_ARTIFACTS`) stamps its own steps `not_executed`. A pull run with `delivered_at` NULL counts as executed only when its output carries a beacon step frame or a `/complete` summary. An unscoped reconcile no longer un-credits a row that is already observed / detected / prevented; retracting an uncredited `UNSCOPED_MATCH` candidate returns it to `pending`.
- **An agent with work owed cannot be deleted.** `DELETE /api/agents/{id}` answers `409 AGENT_HAS_OPEN_RUNS` with `run_ids` while a task is queued for it or a non-terminal run targets it (directly or via the routing ledger). The fix is `POST /api/runs/{id}/abort`; nothing is cancelled implicitly and there is no queued-task TTL (OPS-08 decision open). A newer long-poll supersedes one a restarted beacon left parked, and a superseded or disconnected poll never dequeues the task. A pull launch at an offline target still queues, and now writes `!! TARGET_AGENT_OFFLINE: …` onto `Run.output` as well as into `warnings[]`.
- **Output is bounded, never refused.** A chunk over 1 MiB is accepted and cut. Every step frame line (`=== STEP`, `=== ARTIFACT STAGING`, `--- exit_code=`) and every integrity-marker line is kept, and `[OUTPUT CHUNK TRUNCATED: N of M bytes kept …]` is appended. Stored output is capped at 32 MiB per run with an integrity reserve.
- **`GET /api/runs` pages** (`limit` default 500, max 5000, `offset`) and filters on `status` / `scenario_id` (from `dev`; `total` counts the matching rows). `?fields=summary` drops `output` and adds `output_bytes` + `output_tail`. The console polls the summary and follows `total`.
- **Reconcile is scoped.** An unscoped reconcile match (a push run with no host) stays `pending` / `UNSCOPED_MATCH` with no MTTD, never `detected`. `?host=` on `/reconcile`, or `host` in the `/observations` body, names the endpoint. The summary carries `host_source` (`operator` | `run_target` | null). A push run, every Windows `.ps1` bundle included, is scoped only when the DC passes a host. Keeping this route rather than reverting it to a docs-only "push detect reads pending" is Henry's decision (finding DOCS-03).
- **MTTD is launch-to-alert.** No `run.step` start frames are published and `Result.executed_at` is not re-stamped at step start, so MTTD includes queue wait and earlier steps' runtime. When the clock should start is open (OPS-07).
- **Install attempts reset on restart.** They live in memory (`GET /api/agents/install/attempts`, a deque of 100).

The two paths are not symmetric:
- **Pull — dispatch.** Before this pass the pull path never sent `platform_variants` and ran POSIX primaries in PowerShell, so a step like `SIM-EDR-003` step-01 exited 0 having done nothing and every expectation read `missed`. `orchestrator.resolve_steps_for_target` now resolves each step for `Agent.os` with the push generator's own resolver. It dispatches the resolved command plus `shell` (`powershell` | `cmd`) and `resolved_from`, and writes `!! PLATFORM VARIANT` on variant steps, whose expected detections were authored against a different command. A target OS that cannot run a step is refused at launch with **409 `PULL_TARGET_UNSATISFIABLE`**, before any Result is seeded. A single-endpoint launch at an agent that is not enrolled gets `409 TARGET_AGENT_NOT_ENROLLED`. On the host, the Windows beacon refuses a step whose `platforms` exclude windows. It records `!! STEP NOT RUN: PLATFORM_UNSATISFIABLE step=<id> declared=<platforms> host=windows`, reports the step `not_run` / `PLATFORM_UNSATISFIABLE` (scored `not_executed`, never `missed`) and continues. A run where no step can run completes with exit 78, never 0. POSIX hosts still ignore platform labels.
- **Pull — interpreter.** PowerShell steps run under `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -EncodedCommand`, launched by absolute path, with an explicit `$?` / `$LASTEXITCODE` wrapper that sets BOM-less UTF-8 output. Without the wrapper, `powershell -Command <failing native tool>` exits 0 and a broken TTP reports as a PASS. **`-OutputFormat Text` does not make 5.1 write text.** It is still passed, but Windows PowerShell 5.1 ignores it for `-EncodedCommand` with stderr redirected and writes CLIXML (`#< CLIXML` + `<Objs>`). PowerShell 7 honours it, which is why the round-1 claim held under pwsh 7.6 only. CI runs 42927561143 and 42930052584 showed the envelope on 5.1. The fix: the wrapper's first statement is `$ProgressPreference = 'SilentlyContinue'` (8aa3b51), and `agent/executor/clixml.go` decodes the envelope after capture (d7f4f29), leaving any shape it does not recognise unchanged. Runs 42933820773 and 43037077022 then read stderr and a cmdlet error as plain text. cmd steps run under `%SystemRoot%\System32\cmd.exe /d /c <file>`: the author's text verbatim, CRLF, UTF-8, no `@echo off`. The wrapper truth table is shared with the push bundle: `Write-Output ok` → 0; a native exiting 3 last → 3; a failing cmdlet last → 1; a native writing stderr and exiting 0 → 0. The last row is the BEACON-05 default, pending Henry. All four rows ran under Windows PowerShell 5.1 in the green run's native `go test` (`TestPowerShellExitWrapper_CanonicalTruthTable`; the phase counted `pass=326 fail=0 skip=4`), and the pull probe reproduced the 0 and cmdlet-1 rows through the service. **Agent onboarding** — the front door is the **enrollment-token** flow: mint a TTL/max-uses/revocable token (`POST /api/agents/enroll/tokens`), run one line on the jumpbox (`curl -fsSL '<server>/api/agents/install?os=linux' | CORTEXSIM_TOKEN='cxs_…' bash` — the console emits the token as an env var so it stays out of the URL, the served script and proxy access logs; the pasted line itself **is** in shell history, unless the shell ignores lines with a leading space, so mint single-use, short-TTL tokens), and SimCore *assigns* the agent id via `POST /api/agents/enroll` (no more self-asserted `--id`). Legacy `POST /api/agents/register` + explicit-id installer remain for back-compat. The script needs **no Go toolchain and no public-internet egress on the target**: it downloads the prebuilt beacon from this SimCore and sha256-verifies it (`CORTEXSIM_BIN` pre-staged → download+verify → `CORTEXSIM_SRC` source build → fail). `?mode=service` (default) installs a **systemd unit (Linux) or launchd job (macOS)** so the beacon survives the SSH session and a reboot, degrading honestly to `setsid`+`nohup` with a `DEGRADED_NO_SUPERVISOR` code when no supervisor exists (a `systemctl` binary with no live systemd reports `SERVICE_START_FAILED` and degrades to nohup; on Windows that code is a hard stop); `?mode=foreground` is the old babysat behaviour and `?uninstall=1` returns an idempotent removal script. Run the POSIX uninstaller as the user who installed (`… | bash`); `| sudo bash` is for a root install, and the installer's closing line prints `| sudo bash` only after one. A root run also removes user-mode installs under `SUDO_USER` and under `/home` / `/Users`, and ends `UNINSTALL_INCOMPLETE` if it cannot stop a login's unit. A non-root run removes its own install and fails `NEEDS_ROOT` naming the root items. Driven with stubs under bash 5.3 and 3.2 only, not under a real sudo or systemd. macOS is first-class (`os=macos|darwin`). Every stage exits with a stable code that is both printed and POSTed to `/api/agents/install/telemetry`, readable at `GET /api/agents/install/attempts` (in memory, reset on restart) — so "ran the one-liner, nothing appeared" has an answer. ### Core Module Structure

- `core/main.py` — FastAPI app entry, lifespan handler (init DB → load scenarios → init tool instantiator)
- `core/config.py` — Pydantic Settings from env vars (`CORTEXSIM_PORT`, `CORTEXSIM_ENV`, etc.)
- `core/database.py` — async SQLAlchemy with SQLite at `{BASE_DIR}/data/cortexsim.db`
- `core/models.py` — ORM: Scenario, Run, Result (with MTTD timing), ToolInstance, Agent (all have `.to_dict()`)
- `core/api/` — FastAPI routers: scenarios, runs (with report export), results (with validation), tools, agents, mitre (coverage heatmap data), uctc (UC/TC index read surface), pov (entitlement scoping)
- `core/engine/` — scenario_loader (YAML→DB with Pydantic validation), orchestrator (auto-seeds Result rows from expected_detections), push_generator, uctc_registry (v2.2 index → frozen dataclasses), verifier (scores runs against thresholds)
- `core/tools/` — `registry.py` (static TOOL_REGISTRY dict) + `instantiator.py` (subprocess lifecycle manager)
- `core/planes/` — declarative `PlaneDescriptor` registry, one frozen-dataclass module per active plane (edr, cdr, ndr, itdr, cloud_app, analytics, ai_access, airs, ai_spm, asm, browser, cspm, koi, tim); `base.py` defines the descriptor model and `__init__.py` the registry

### Key Data Flows

- **Run launch** → orchestrator creates Run record → auto-seeds Result rows from scenario `expected_detections` (one per detection per step) with `executed_at` timestamp
- **Detection validation** → DC marks results as observed via `PUT /api/results/{id}/validate` → sets `observed_at` → `mttd_seconds` computed as `observed_at - executed_at`
- **Report export** → `GET /api/runs/{id}/report?format=markdown` generates Cortex-branded POV report with coverage stats and MTTD metrics
- **MITRE coverage** → `GET /api/mitre/coverage` aggregates technique coverage across all scenarios/runs for the heatmap UI

### Key Design Rules

- **No wrapper code around external tools.** The Tool Instantiation Layer calls real binaries with their native CLI flags. SimCore is the process manager, not a translation layer. `TOOL_REGISTRY` holds `run_template` strings formatted and passed to `subprocess.Popen`.
- **Scenarios are YAML source-of-truth.** DB stores run history only. Scenarios load from `scenarios/` on startup.
- **Schema validation is strict.** Scenario loader validates every YAML against the Pydantic schema derived from `scenarios/_schema.yml`. Invalid files are rejected at startup.
- **All API responses are structured JSON** — including errors: `{"error": "...", "code": "...", "detail": "..."}`.
- **Push bundles must be self-contained.** A bash bundle executes on clean Ubuntu 22.04, and a `.ps1` targets Windows PowerShell 5.1 (Server 2016+ / Windows 10+), with no SimCore dependency at runtime. The `.ps1` floor is authored and gated by parse only: no bundle has executed on Windows.
- **Dataset prerequisites are derived from a registry, not authored per scenario.** `spec/dataset_requirements.yml` (32 datasets, one per dataset a card reads through a query's `dataset` or a `dataset =` / `preset =` anchor in its logic) states what each needs on the Cortex side and the source side; `core/engine/prerequisites.py` derives a scenario's list through the cards it cites, served at `GET /api/prerequisites/datasets`, `/api/scenarios/{id}/prerequisites` and `/query-library`. An **absent registry is degraded** (200, `registry_loaded: false`, health `DATASET_REGISTRY_ABSENT`), a **malformed one raises** (structured 500; boot refuses only under `CORTEXSIM_STRICT_DATASETS=true`), and a cited card with no entry is `UNREGISTERED_DATASET`, never "no prerequisite". Rows read `from documentation` or `confirmed in a tenant`; none is confirmed, so ***tenant-verified is 0***. Reference: `docs/reference/dataset-requirements.md`.

## Scenario YAML

Scenarios live in `scenarios/{plane}/` (e.g., `scenarios/edr/edr-001-credential-dumping.yml`). Schema reference is `scenarios/_schema.yml`. ID format: `SIM-{PLANE}-{NNN}`.

Every scenario has: UC/TC alignment refs, MITRE ATT&CK mapping, execution identity config, ordered steps with expected detections per step, and cleanup commands.

**Causality contract (optional, additive, back-compat).** Scenarios without these fields load unchanged; declaring them collapses the causality graph's synthetic `cortexsim-agent` star into one connected CGO→process→process spine (`core/engine/causality_graph.py`). The scenario loader + `.claude/hooks/lint-scenario.py` validate all four:
- **`cgo_anchor`** (scenario-level): `{image_name, primary_username?}` — the realistic initial-access process that OWNS the chain (e.g. `apache2`/`www-data`, a phishing `winword.exe`, a k8s runtime). Labels/names the CGO root node instead of the default `cortexsim-agent`/`root`. Persisted to the `Scenario` ORM (`cgo_anchor` JSON column, added to an existing DB automatically at boot by `database._migrate_*`; do not `ALTER TABLE` by hand, SQLite rejects the duplicate column).
- **`causality`** (per-step): `{parent_step, pivot?}` — this step's process descends from an EARLIER step's process via the declared edge kind. The loader rejects forward/self refs and allows at most one root step (the step that omits `causality`, which links from the CGO). `pivot` ∈ `process_lineage · network_session · endpoint_network_stitch · shared_entity · exposure_exploit · exploit_impact · temporal` (default `process_lineage`). A `process_lineage` pivot chains parent→child process nodes; any non-process pivot emits its own typed edge and leaves the step rooted at the CGO.
- **`platforms`** (per-step): subset of `linux · windows · macos · container · k8s`.
- **`platform_variants`** (per-step): `{os: command}` per-OS equivalents so a cross-platform TTP is exercised across environments (keys must be in the enum; lint warns if a key isn't also in that step's `platforms`).

**Composer canvas layout (2026-09-08).** `Scenario.composer_layout` is a separate, presentation-only JSON column — `{"<step_id>": {"x": int, "y": int}}` — for the Composer's drag-and-drop node positions. Deliberately NOT part of the scenario YAML schema or `steps[]`: it is set/read only through `POST`/`PUT /api/scenarios/drafts`, never reaches the strict corpus loader, and stays NULL for every shipped scenario. Same nullable-JSON pattern as `cgo_anchor` / `stitch_context`, and the same boot migration adds the column (round 1 built DBs with v0.1.0, v1.0.0, v1.0.2 and v1.1.0 code and found no column or index missing after the current `init_db`). **Rolling back is not symmetric (OPS-17, open):** a DB created by current code has `runs.agent_profile_mode` and `results.expected_outcome` as `NOT NULL` with no SQL default, so v1.0.2 / v1.0.0 code inserting into it fails every launch. There is no schema stamp. Back up the `simcore_db` volume before an upgrade and restore that backup to roll back (`docs/release/mvp-launch-runbook.md` §8.5).

`Agent.runtime_facts` (container-agent facts, nullable JSON) is auto-migrated at boot; by hand: `ALTER TABLE agents ADD COLUMN runtime_facts JSON`.

`Run.case_ledger` (the run case ledger, nullable JSON) is auto-migrated at boot; by hand: `ALTER TABLE runs ADD COLUMN case_ledger JSON`.

**Composer mode (2026-10-21).** The Composer is a full-screen node graph: its destination declares `immersive: true`, so the shell drops the nav rail, tab strip and view padding (route-derived, never persisted) and the surface gets an optional `onExit`. Graph topology comes from the pure `ui/src/components/console/composerGraph.js` — CGO trigger, steps and Proof are all React Flow nodes; only `steps[].causality` edges and step positions persist, the trigger/terminal and their edges are derived. Three rules to keep: `validateDraft`/`spineProblems` must match `validate_causality_spine` (one root once any parent is declared, no parent at a later index); `edited` compares the launch-relevant snapshot, because an un-edited draft launches the ORIGIN corpus row; and a fork must carry every field the draft contract accepts — `external_tools` drives the launch consent gate and payload staging, so dropping it runs a gated tool without either; `indicators[]` and the re-derived `pull_supported` sit outside that contract and are not carried, while `threat_report*` is carried and `push_supported` is carried only as a refusal floor (see *Fork push floor* below). ## UC/TC Alignment (FY27 v2.2 index)

The FY27 Use-Case / Test-Case master index is the sales-motion source of truth. Its versioned snapshot lives at `docs/uc_tc_mapping/_v2.2-source/` (**49 UC · 203 UCS · 266 TC · 140 POV-SC payloads · 38 SKU**) and is loaded at boot by `core/engine/uctc_registry.py` into frozen dataclasses.

**Scenario refs are a validated foreign key into that index, not free text.** Every scenario carries `uc_ref`, `tc_ref` (primary), `tc_refs[]` (the full evidence set, always containing `tc_ref`), and `pov_scenario_id`, plus the measurement contract (`validation_methodology`, `methodology_family` F1..F10, `primary_kpi`, `threshold`, `success_criteria`, `moat_tier`, `correlation_window_seconds`, `stitching_key`, `required_planes_in_incident`). `required_base_platform` / `required_addons` are **derived at load** from the registry, never authored. `core/engine/scenario_loader.py` enforces codes **S-10** (`tc_ref` not in index, ERROR) · **S-11** (unknown `uc_ref`, ERROR) · **S-12** (`tc_ref` parent ≠ `uc_ref`, ERROR) · **S-13** (tier disagreement, WARNING) · **S-14** (bound TC is POS/PLT/AUT, WARNING) · **S-15** (dangling `tc_refs[]` entry, ERROR) · **S-16** (unknown `pov_scenario_id`, WARNING). ERRORs reject only when `CORTEXSIM_STRICT_REFS` is true — **it defaults true**. If the snapshot is absent the registry degrades to advisory and never rejects, so a stripped deploy still boots.

**In-product surface.** `core/api/uctc.py` serves the index read-only at `GET /api/uctc/{summary,use-cases,use-cases/{id},test-cases,test-cases/{id},coverage,gaps,payloads,by-scenario/{id}}`, joined to the engine's own evidence (`Scenario.tc_refs` → `Run.tc_verdict`). The console destination is **Reference › Catalog › UC / TC index** (`ui/src/components/console/UcTcIndexView.jsx`, `#/uctc`, deep-linkable via `?uc=&tc=`). `core/api/pov.py` scopes the corpus to a tenant entitlement set (`GET /api/pov/profiles`, `/capabilities`, `POST /api/pov/scope`) and generates the upsell list with real `PAN-*` part numbers. Every `/api/uctc` response carries `{index_loaded, index_version}` — a snapshot-less deploy returns **200 with `index_loaded: false`**, which callers must render as degraded, never as "0 test cases".

**Do not "fix" these.** S-13 tier disagreements (127 counted 2026-11-12 by `scripts/uctc_crosswalk_v2.2.py --report`, the ground truth's `tier_drift_s13`; 100 when the gaps doc was written) and S-14 posture bindings (14; then 13) are deliberate positioning calls (see `docs/uc_tc_mapping/index-gaps-v2.2.md`). 57 of the 107 detection-backable TCs carry no measurable threshold (`is_scoreable: false`) and are surfaced as such. Evidence never joins through `pov_scenario_id` — `POV-SC-001` alone binds 21 test cases. Three namespaces have historically been called "UC"/"TC"; only the index is canonical — `detection_scanner/ttps/*.json` uses card-local `threat_scenario_id` (`TS-*`) / `threat_step_id` and a guard test fails if a card id ever takes a `UC-`/`TC-` prefix again. Current state (re-counted 2026-11-12): **199/199 scenarios resolve, zero S-10/S-11/S-12/S-15/S-16; 90 of 266 index TCs evidenced by a scenario (70 of 107 DET/HNT)**; 37 DET/HNT rows remain unevidenced. `make check-refs` (CI job `refs`) walks the real corpus through the loader under strict mode — that gate is what makes the enforcement meaningful. Authoritative doc: `docs/uc_tc_mapping/README.md`; the crosswalk is hand-authored in `scripts/uctc_crosswalk_v2.2.py` (`--report` / `--emit` / `--apply`).

**Assertions — the second proof mechanism (POS/PLT/AUT).** 140 of the index's open rows are **not detections** and cannot be closed by authoring more scenario YAML: POS asks whether a posture state *holds*, PLT whether a capability is *present*, AUT whether an outcome *occurs inside a budget*. `core/engine/assertions.py` + `assertions/{pos,plt,aut}/*.yml` are the artifact type for those, mirroring `Scenario`/`Run`/`Result` with `Assertion`/`AssertionRun`/`AssertionCheck` so **`verifier.score_run` scores both with no parallel scorer** (it gained two defaulted kwargs, `measured_value` and `tc_scoreable`; all 162 scenarios score byte-identically). An artifact carries two discriminators — `validation_class` (POS|PLT|AUT, must equal the bound index row's) and `kind` (`state`|`outcome`, where `outcome` mandates a `settle` block). Five read-only XQL probes ship: `xql_rows`, `xql_distinct`, `xql_scalar`, `xql_ratio` (refuses to call 0-of-0 100%), `xql_latency` (measures `outcome_ts − precursor_ts` in the *platform's* clock, never wall-clock). Thresholds live in the artifact, never in the query — `| filter sla <= 300` returns zero rows for a tenant that took 412 s, indistinguishable from one that never responded.

**The guard: an assertion that cannot fail does not load, proven by execution at load time.** `A-17` builds measurements across the probe's own declared domain (`count` [0,∞), `seconds` [0,∞), `percent` [0,100], `ratio` [0,1]) plus the neighbourhood of the authored threshold, pushes each through the *real* evaluator, and rejects unless the check produces **both** a `fail` and a `pass` — so `expected_rows_min: 0` on a row count is rejected with *"this check can never fail and therefore proves nothing"*. `A-18` requires an authored `negative_control {description, measured_value}` and proves that value is inside the probe's physical domain *and* really evaluates `fail`. `A-17`/`A-18`/`A-19`/`A-20`/`A-21`/`A-22`/`A-24` are **structural and are NOT gated by `CORTEXSIM_STRICT_REFS`** — only the index-binding codes `A-10..A-16` are, exactly as `S-10..S-15` are for scenarios. `A-14` is the *inverted* `S-14`: a scenario binding a POS row warns, an assertion binding a DET row is an ERROR. Ref validation goes through one shared `validate_index_refs()` in `scenario_loader.py`. **No tenant is never green:** no integration / unreachable / 401 / 429 / bad dataset / `PRECURSOR_MISSING` / `POPULATION_EMPTY` / dry run all resolve **`pending`**; only `NOT_ENTITLED` (plus the unscoreable clamp) resolves `not_applicable`, because collapsing "still owed" into "unscoreable by construction" would let unproven claims vanish into a bucket that reads benign. A test case whose index row is `is_scoreable: false` clamps PASS → `not_applicable` ("this is evidence, not a scored pass"); **FAIL is never clamped** — you can disprove a qualitative claim, you just cannot machine-certify it passed. API: `GET /api/assertions` (surfacing `rejected[]` — a guard nobody can see is not a guard), `/probes`, `/{id}`, `POST /{id}/run` (`dry_run` defaults **true**), `GET /runs`, `/runs/{run_id}`. Contract + authoring guide: `docs/uc_tc_mapping/assertions.md`.

### The payload shelf — staged, digest-pinned tool artifacts

**The problem it exists for.** Every tier-4 pack installs its tool **from the public internet, on the target host, at dispatch** (`command -v hydra || apt-get install -y hydra`). Customers who buy Cortex run default-deny egress, so that is the first thing their network blocks. A step whose tool never arrived **runs anyway**, produces no detection, and the absent detection reads in a POV report as *"Cortex missed it"* — a manufactured false negative on the customer's stack, in a document a DC shows a customer.

A tier-4 pack may declare **one** staged artifact, `install.artifact` (`filename`/`url`/`kind: file`/`sha256`/`pin`/`license`/`stage_path`/`mode`), validated by seventeen **`TA-01..TA-17`** codes in `adapter_loader.py` (`TA-` and not `A-`, because `assertions.py` already owns `A-10..A-24`). `payloads/sources.json` is **generated** from those declarations (`python3 -m engine.payload_shelf --write|--check`), never hand-maintained. `scripts/build-payloads.sh` stages the bytes onto the DC's own SimCore; `PAYLOAD_ALLOW_UNPINNED=0` refuses an unpinned build. One resolver — `core/engine/payload_shelf.py::compose()` — walks `scenario → adapter_ref → pack → artifact → shelf` and **refuses at compose time** with `PAYLOAD_NOT_STAGED` or `PAYLOAD_PIN_MISMATCH` (409). Served plane-agnostically at `/api/shelf/{payloads,payload/{name},payload/{name}/sha256,artifacts,compose,resolve/{id},stage}`; `/api/k8s/*` stays mounted forever from the **same handler functions** because emitted manifests hard-code those paths in customers' GitOps repos.

**The integrity model — do not fork it.** The digest is recomputed from the shelf bytes on the DC's own SimCore at compose time and baked into whatever the consumer carries. The consumer verifies against a value it **carried in**, never one it fetched from the server it is trusting. The **destination path** — never the shelf key — is overridable (`artifact.stage_path ← external_tools[].stage_as ← request override`), which is what makes a **rename negative control** expressible: stage linpeas as `/tmp/.cache/sysinfo.sh` and the filename-keyed BIOCs correctly go dark while behavioural ones must still fire. Every rename emits `FILENAME_KEYED_DETECTIONS_SUPPRESSED` stating the inverted reading.

## IaC Topology Generator

The IaC generator produces Terraform bundles Torque can consume as blueprints. Phase A supports AWS with `base`, `edr`, `cdr`, and `content-library` modules. The DC selects modules + parameters in the UI and downloads a tar.gz bundle containing a ready-to-apply root Terraform config plus all selected module directories.

### Key paths

- `infra/modules/{provider}/{module}/` — Terraform modules (+ `content.yml`, `README.md` with YAML frontmatter)
- `infra/templates/*.j2` — Jinja2 root-bundle templates rendered by the generator
- `infra/blueprints/` — generated bundles (gitignored)
- `core/engine/infra_generator.py` — core generation logic (uses `shutil.copytree` with ignore callback to strip `.terraform/` artifacts)
- `core/engine/infra_catalog.py` — module metadata loader (reads README.md frontmatter + content.yml)
- `core/engine/infra_models.py` — Pydantic request/response models
- `core/api/infra.py` — `/api/infra/*` endpoints
- `core/content_loader.py` — merges `/opt/cortexsim/content/installed.json` into TOOL_REGISTRY at startup
- `core/tools/registry.py` — now exposes `STATIC_TOOL_REGISTRY` (built-ins) and runtime `TOOL_REGISTRY`
- `scripts/jumpbox/install-content.sh` — runs on provisioned jumpbox via cloud-init; clones/installs each module's declared content

### API endpoints

- `POST /api/infra/generate` — generate a bundle, returns `bundle_id` and `download_url`
- `GET  /api/infra/modules[?provider=aws]` — list available modules
- `GET  /api/infra/bundles` — list previously generated bundles
- `GET  /api/infra/bundles/{bundle_id}/download` — download tar.gz

### Design rules (IaC-specific)

- **Base module always included** in any bundle (enforced in `InfraGenerator._normalize_modules`).
- **Static TOOL_REGISTRY always wins** over installed-content entries — `content_loader` never overwrites.
- **Module metadata lives in `README.md` frontmatter**, not in Python — adding a module is filesystem-only.
- **Bundles are stateless artifacts** — no DB schema. File-system is source of truth.
- **Never commit `.terraform/` or `.terraform.lock.hcl`** into module directories — they pollute generated bundles. The generator also strips them via an `ignore` callback.

### Scenario schema additions

Scenarios may optionally declare `required_content` (open-source tool repos needed) and `infra_modules_needed` (IaC module names to pre-select). Both default to empty lists — existing scenarios load unchanged.

### Tests

Python tests live under `tests/`. Run: `.venv/bin/pytest tests/ -v`. The suite covers Pydantic models, module catalog, generator (including a regression guard that bundles don't contain `.terraform` artifacts), API endpoints, and content loader. The `tests/conftest.py` sets `CORTEXSIM_BASE_DIR` to the repo root via `setdefault` so tests resolve `infra/modules/` correctly.
