# UC/TC Full-Coverage Sprint Plan (v2.3)

**Goal:** a specific, engine-backed detection or simulation for every one of the
266 test cases in the FY27 v2.2 index, with DC-facing guidance for every TC that
needs an external platform.
**Method:** [`docs/superpowers/specs/2026-09-04-uctc-full-coverage-design.md`](../superpowers/specs/2026-09-04-uctc-full-coverage-design.md)
**Cadence:** 2-week sprints. **Date:** 2026-09-04.

---

## Executive summary

The index holds 266 test cases; the live engine evidences ~90 today. The remaining
~172 are **not** mostly detections — ~150 are posture/platform/automation
assertions, most tied to an external platform. The plan closes all 266, sequenced
by **dependency risk, not raw count**: it front-loads the ~40 detection and
network rows we control end to end, defers the 108-row posture bucket behind the
LaaB team's approval of lab fixtures, and runs the harder SaaS/O365 log ingestion
as a parallel long-term track that needs live-tenant confirmation before it can be
trusted. Every "closed" TC means an artifact exists **and** its guard reddens
without the fix; `tenant-verified` stays a separate number that only a live-tenant
run can move, and today it is zero.

### Definition of done

A TC is **closed** when `authored AND fails_without_fix`:
- an engine artifact (scenario or assertion) binds the TC, and
- its guard demonstrably reddens without the fix (Gate A5 negative control;
  `A-17`/`A-18` for assertions).

`tenant_verified` is a **separate** column, advanced only by a live-tenant run,
and never counted as closure. `status: blocked(<dep>)` marks a TC that is authored
but whose *usability* is gated on an external party (e.g. LaaB); it is reported as
an external dependency, not as our incomplete work.

### P0 · Instrument — 1 sprint (no external gate)

Stand up the machinery the whole plan reports through. Nothing else starts until
the scoreboard can move on its own.

- **P0.1** Implement the §4 decision procedure as a crosswalk pass; classify all
  ~172 open TCs into `{M1, M2-quick, M2-longterm, M3, M4, M5}`; write the per-TC
  binding record (§5).
- **P0.2** `--emit-xlsx`: regenerate the "Engine Coverage v2.3" sheet keyed by
  UC/TC ID into a copy of the workbook; add `--emit-xlsx --check` to CI (existing
  `refs`/`detection` job, fail-closed).
- **P0.3** Task **L0** — enumerate the Cortex "alerts by data source" catalog; emit
  the coverage matrix (`data_source · detectors · emitter? · KNOWN_DATASETS? ·
  delivery_paths_proven`) as the second sheet + a markdown mirror.
- **P0.4** Regenerate the scoreboard from `--report`; wire it into the ground-truth
  docs so the plan's numbers and the sheet's numbers are one source.

**Exit:** every open TC carries a recorded mechanism; the mapping sheet regenerates
and is CI-guarded; the L0 gap list exists and drives P1/P-LT ordering.

### P1 · Quick wins — 2–3 sprints (fully controlled)

The rows we own end to end. Signal is generated by the identity harness (M1) or by
emitters whose data shape we control (M2-quick: NGFW EAL, DNS, C2,
signalbench-shaped endpoint/network telemetry). No external platform, no external
gate — the scoreboard moves in week 2.

- **P1.1** Author M1 scenarios for open DET/HNT keyed on endpoint/process/network
  causality; one TTP card per scenario; each with a fails-without-fix guard.
- **P1.2** Author M2-quick emitters/scenarios for open DET/HNT keyed on
  network/endpoint ingested sources; prove detection objects fire through all
  three delivery paths (connector, BVM, API).
- **P1.3** Close the L0 gaps flagged `M2-quick` — build the missing
  network/endpoint emitters, register datasets, drive the coverage metric up.

**Exit:** open DET/HNT → ~0 (authored + fails-without-fix); M2-quick portion of the
L0 matrix at target; scoreboard reflects the jump.

### P2 · Posture, provider-split — 3–4 sprints (LaaB-gated closure)

The biggest bucket (108 POS) and the one blocked on an external team. **We author
on schedule; closure waits on LaaB.** Split by cloud provider so a stall in one
does not stall the others.

- **P2.A** AWS POS — author POS assertions against the AWS IaC modules' planted
  findings (CSPM/KSPM heavy); each with a negative control (`A-18`).
- **P2.B** Azure POS — same, Azure modules (Phase D IaC dependency noted).
- **P2.C** GCP POS — same, GCP modules (Phase C IaC dependency noted).
- **P2.D** Every P2 TC lands at `status: blocked(laab)` until fixture usability is
  approved; the scoreboard shows these as an external dependency, distinct from
  "not authored."

**Exit:** POS assertions authored per provider with negative controls; each TC's
blocker explicitly attributed to LaaB, not to us.

### P3 · Platform-state — 2 sprints

39 PLT rows via M4 read-only XQL assertions (`xql_rows`/`xql_scalar`/`xql_ratio`),
thresholds in the artifact never in the query. No provisioning; a read-only probe
against a tenant when one exists, `pending` otherwise.

**Exit:** PLT assertions authored, each proven to be able to fail (`A-17`).

### P4 · Automation — 1 sprint

3 AUT rows via M5 outcome assertions with a `settle` block, plus the
correlation-terminal metrics (XSOAR playbook fired / SLA measured against
`xsiam_incidents`). Latency measured in the platform's clock, never wall-clock.

**Exit:** AUT assertions authored with negative controls.

### P-LT · Robust log-sim — parallel long-term track

The M2-longterm subset: O365 / M365 / Google Workspace / identity-cloud SaaS
ingestion. These need live-tenant field confirmation before the dataset strings and
field shapes can be trusted, so they do **not** ride the quick-win track. Authored
here are labelled authored-but-unproven until confirmation.

- **P-LT.1** Field-confirm each SaaS/O365 dataset against a real ingest (or record
  the assumption + caveat where no tenant is available).
- **P-LT.2** Build the M2-longterm emitters; prove delivery accounting; register
  datasets.
- **P-LT.3** Author the dependent DET/Correlation TCs; mark unproven until P6.

**Exit:** M2-longterm emitters exist with honest unproven labelling; the robust
solution is documented, not faked.

### P6 · Tenant-verify — last

Turn the `tenant_verified` 0→N column on where tenant access exists. Tier-2 verify
(`POST /api/runs/{id}/verify`) and reconcile read-back convert `authored` →
`proven`. Quota-disciplined; a spent budget degrades to `pending`, never `fail`.

**Exit:** first real-tenant greens recorded, honestly separate from the authored
count.

## Cross-cutting workstreams

- **Runbooks (§7 of the spec).** One `docs/uc_tc_mapping/external-platforms/
  <platform>.md` per external platform, produced alongside the phase that touches
  it (AWS/Azure/GCP during P2, Okta/M365/etc. during P-LT). This is the
  "detailed guidance" deliverable.
- **Mapping sheet.** Regenerated every sprint from `--emit-xlsx`; the durable,
  index-keyed answer to "map coverage back to the UC/TC IDs."

## Risk register

- **Reporting authored as proven.** Mitigated: three-state model, separate
  `tenant_verified` column, CI-guarded sheet.
- **A tolerant fix greening a broken guard.** Mitigated: `A-17`/`A-18` and Gate A5
  negative controls are mandatory for closure.
- **P2 stalling the plan.** Mitigated: dependency-risk sequencing puts P2 after the
  ungated P1; P2 authoring proceeds even while closure waits on LaaB.
- **O365 emitters shipping a wrong dataset string.** Mitigated: M2-longterm is a
  separate track with explicit field-confirmation gating and unproven labelling.

## Tracking

Progress is the crosswalk scoreboard, regenerated per sprint. A sprint is done when
its exit criteria hold and the mapping sheet reflects the new `authored` /
`fails_without_fix` counts. `tenant_verified` is reviewed separately and never used
to declare a sprint complete.
