Bottom line up front

CortexSim drives controlled, high-fidelity signal into a customer's XSIAM or XDR tenant so a DC can prove detection logic against the same UC/TC the customer is buying — 170 scenarios across 15 detection planes, every one a validated foreign key into the FY27 v2.2 index rather than a generic atomic test.

The number that governs how you use it is the last one: tenant-verified is 0. The corpus is authored and it loads clean, but nothing in this repository has executed against a live Cortex tenant. Authored is not proven, and the engine is built to keep those two apart rather than average them together.

01

What the engine does

Not a red-team C2 — a detection quality-assurance engine. Real binaries, real process causality, real telemetry.

SimCore loads a YAML corpus, resolves each step's service-account identity, and delivers the step to the customer's environment by one of three surfaces. Signal flows one way, into the tenant. The read-back path that closes the loop into measured MTTD is opt-in, read-only, and off until a credential is configured — SimCore never writes to Cortex.

02

What the corpus covers

170 scenarios decompose into 654 executable steps carrying 1096 expected detections across 14 MITRE ATT&CK tactics.

Counts are re-measured by running the engine's own loader over the tree, not estimated from file counts. The two differ: the tree holds 175 scenario YAMLs and the loader accepts 170 — the DLP plane is authored but rejected, and a count that reported 175 would be the exact false-green the loader exists to catch.

03

Detections are not the only proof

140 rows in the FY27 index are not detections at all, and no amount of additional scenario YAML can close them. A posture question asks whether a state holds; a platform question asks whether a capability is present; an automation question asks whether an outcome lands inside a budget. Those get assertion artifacts, scored by the same verifier as scenarios — no parallel scorer.

ArtifactAsksCount
ScenarioDoes the detection fire?170
POSDoes a posture state hold?13
PLTIs a capability present?4
AUTDoes an outcome hit its budget?3

An assertion that cannot fail does not load. At load time the guard builds measurements across the probe's declared domain plus the neighbourhood of the authored threshold, pushes each through the real evaluator, and rejects the artifact unless it produces both a pass and a fail. A row-count check written as expected_rows_min: 0 is refused with "this check can never fail and therefore proves nothing."

04

How far the evidence goes

Four rungs, never collapsed into one number. A scenario that loads is not a scenario that ran, and a scenario that ran against a mock is not evidence about a customer's tenant.

Read this before quoting a coverage number

The index is not one population. Of its 266 test cases, 94 are evidenced by a scenario or an assertion and 172 remain open — but only 91 carry a measurable threshold at all. A flat percentage hides which mechanism owes the work, and none of it is tenant-verified.

05

Getting it running

CortexSim is distributed as source. There is no tagged release and no published container image — the release pipeline exists and fires on a v*.*.* tag, but no tag has been cut. Everything you run comes from the tree.

Docker — canonical bring-up

git clone https://github.com/__GH_OWNER__/__GH_REPO__.git
cd __GH_REPO__
cp .env.example .env
./scripts/dev-up.sh

No Docker

./scripts/dev-up-native.sh              # full bring-up
./scripts/dev-up-native.sh --skip-ui    # reuse core/static/
./scripts/dev-up-native.sh --stop       # stop

Enroll a beacon on a target host

curl -fsSL '<server>/api/agents/install?os=linux' \
  | CORTEXSIM_TOKEN='cxs_…' bash

No Go toolchain and no public-internet egress required on the target — the beacon is downloaded from your own SimCore and sha256-verified, then installed as a systemd unit or launchd job so it survives the SSH session. That property is the same reason the payload shelf exists: customers who buy Cortex run default-deny egress, and a tier-4 tool that never arrived produces no detection, which reads in a POV report as "Cortex missed it" — a manufactured false negative on the customer's own stack.
